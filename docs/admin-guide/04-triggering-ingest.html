Triggering the Ingest

There are two ways files get picked up from 01-Inbound and processed: an automatic schedule, and a manual trigger. Both run the exact same process across every configured document library – the only difference is what starts it.

Automatic (scheduled) runs

The application can run on a recurring schedule (by default, hourly) without anyone doing anything. On each scheduled run, it works through every configured document library in turn, checking each one's 01-Inbound folder for new PDFs.

Whether the schedule is currently turned on, and exactly how often it runs, is an environment-specific setting controlled by the platform/development team. If you're not sure whether the schedule is active in your environment, ask them, or use the Job Logs list – every run, scheduled or manual, adds an entry there, so you can see from the timestamps whether scheduled runs are happening.

Manual trigger

The application also exposes a manual trigger that runs the same process on demand, without waiting for the next scheduled run. This is useful when:

  • You've just uploaded files and don't want to wait for the next scheduled run
  • You're testing that everything is configured correctly after a change
  • The scheduled run is turned off in your environment (e.g. during initial setup)

Triggering it requires calling a specific URL for your environment (ask your development/platform team for the exact address, as this differs between environments). Calling it starts a full run across every configured library, exactly like a scheduled run would.

How to tell a run actually happened

After triggering – manually or on schedule – check the Job Logs list. A new row will appear for each document library, with a timestamp, so you can confirm the run took place and see the outcome at a glance.
