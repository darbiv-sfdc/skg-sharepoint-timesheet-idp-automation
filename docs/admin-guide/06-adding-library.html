Adding or Removing a Document Library

When a new business unit or site needs to start using the application, a new document library needs to be set up in SharePoint and then registered with the application. This is a joint task – some steps are yours, and one step needs your development/platform team.

Step-by-step

  1. Create the document library. In SharePoint, create a new document library named after the new business unit or site (e.g. matching the style of existing libraries like EKN or FLEET).
  2. Create the five standard folders inside it, using the exact same names as every other library: 01-Inbound, 02-Processing, 03-Output, 04-Processed, 99-Error. See Document Library & Folder Structure for what each one is for. The names must match exactly – the application looks for these folders by name.
  3. (Recommended) Add the same classification columns used elsewhere – PDF Type, Site, Week No. – if you want the new library to be filterable the same way. See Classifying Timesheet PDFs.
  4. Grant the application's service account access to the new library (see Permissions & Access).
  5. Ask your development/platform team to register the new library. This is a configuration change (adding the library's name to a settings file) that requires a deployment – it is not something that can be done from SharePoint alone. Give them the exact library name you used in step 1.

Once your development team confirms the change is deployed, the new library will be picked up automatically on the next scheduled or manually triggered run – no further action needed on your side.

Removing a library

Removing a library from active use is the reverse of step 5 above – ask your development team to remove it from the same settings file and redeploy. The document library itself and its historical files in SharePoint are not deleted by this; it simply stops being scanned for new files.
