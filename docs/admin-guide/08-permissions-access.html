Permissions & Access

Two different kinds of access are relevant to this application: the access the application itself needs to work with SharePoint, and the access people need to use and manage it.

What the application needs

The application connects to SharePoint using its own dedicated service account/app identity – it does not use any individual person's login. For every document library it manages, this identity needs enough permission to:

  • List and read files in 01-Inbound
  • Move files between all five folders (Inbound → Processing → Output/Processed/Error)
  • Create new files (the extracted CSV) in 03-Output

In practical SharePoint terms, this means Edit/Contribute access on each document library the application manages. It also needs Contribute access on the Mule IDP Job Logs list, since it creates a new item there on every run.

When onboarding a new library (see Adding or Removing a Document Library), granting this same access to the application's identity on the new library is one of the required setup steps.

What people need

TaskSuggested access level
Uploading timesheets, filling in classification columns, reviewing Output/Processed/Error Standard library Read/Contribute access, same as any other SharePoint library
Viewing the Job Logs listRead access to the list
Triggering a manual runRestricted to administrators/developers – this calls an internal application endpoint, not a SharePoint permission
Changing configuration (libraries, schedule, timeouts, etc.)Restricted to the development/platform team – requires a deployment, not a SharePoint permission

As a general rule: anyone who works with timesheets day to day only needs ordinary access to the document libraries and the Job Logs list. Anything that changes how the application behaves should go through your development/platform team.
