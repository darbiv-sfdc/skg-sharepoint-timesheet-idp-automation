Job Logs

Every time the application runs – scheduled or manually triggered – it writes one row per document library to a SharePoint list called Mule IDP Job Logs. This is the fastest way to see what happened on a run without opening any folder.

Columns

ColumnMeaning
TitleLibrary name and run timestamp, e.g. EKN_2026-08-19T14:37:13
ExecutionTimeWhen this run for this library happened
SourceFolderWhich document library this row is about (e.g. EKN, FLEET)
ExecutionTypeScheduled or Manual – how the run was started
FilesProcessedHow many files were successfully submitted for processing
ErrorCountHow many files failed during submission
StatusSuccess, Partial Success, or Failed – see below
DetailsFile names that were processed, and/or error messages for any that failed

Making sense of Status

  • Success – every file found in that library's 01-Inbound was submitted without error. This includes the case where there were no files at all – you'll see FilesProcessed = 0 and Details = "No files found". That's expected, not a problem – it just confirms the run happened and the folder was empty.
  • Partial Success – some files were submitted successfully, but at least one failed. Check the Details column for which file(s) failed and why; the failed file(s) will be in 99-Error.
  • Failed – the run for that library couldn't even get started (for example, SharePoint was temporarily unreachable). No files were processed at all in this case. Check Details for the reason, and try again later or contact your development team if it keeps happening.

Important limitation

A row in this list only tells you that a file was successfully handed off to the IDP service for data extraction – it does not yet tell you whether the extraction itself ultimately succeeded. That result shows up later, per file, as the file lands in either 03-Output/04-Processed (success) or 99-Error (failure) – see Document Library & Folder Structure. In short: use the Job Logs list to confirm a run happened and see a quick summary, and use the folders to see the true final outcome for a specific file.
