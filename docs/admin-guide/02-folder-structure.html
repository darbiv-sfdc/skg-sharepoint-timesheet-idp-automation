Document Library & Folder Structure

Every document library the application watches (for example EKN, FLEET) is set up with the exact same five subfolders. This consistency is what lets the application manage any number of libraries without special-casing any one of them.

The five folders

FolderPurposeWho puts files there
01-Inbound Drop zone for new, unprocessed timesheet PDFs You (or whoever uploads timesheets)
02-Processing Files currently being worked on by the application. A file only stays here for the duration of one processing run. The application, automatically
03-Output The extracted data, as a CSV file, for every successfully processed PDF The application, automatically
04-Processed Archive of original PDFs that were successfully processed The application, automatically
99-Error PDFs that could not be processed – extraction failed, or the request timed out The application, automatically

What's safe to do manually

  • Safe: uploading new PDFs to 01-Inbound.
  • Safe: reading, downloading, or filtering files in 03-Output and 04-Processed – these are your results and archive, and the application never touches them again once they're written.
  • Safe: reviewing files in 99-Error, and moving a corrected file back into 01-Inbound to have it reprocessed on the next run (see Troubleshooting & FAQ).
  • Avoid: manually moving or deleting files inside 02-Processing. The application uses this folder to know which files are currently in flight; interfering with it while a run is in progress can cause a file to be skipped or duplicated.

One library per business unit or site

Each document library represents one business unit (e.g. a company site or division). All of a library's files, output, and archive stay within that same library – the application never writes one library's results into another's folders. If your organization needs to add a new business unit, see Adding or Removing a Document Library.
