Timesheet Automation – UAT Plan: Test Scenarios

Run these test cases in order – later ones build on files created by earlier ones. Record your result for each one in the results tracker. Required test cases must all pass for this UAT to be accepted; Optional ones should be attempted and recorded but don't block acceptance on their own.

TC-01 – Trigger the Ingest On Demand (Required)

Purpose: Confirm a run can be started on demand and covers every configured document library.

Preconditions: All Inbound folders are empty (or you're fine with whatever is already there being processed).

Steps:

  1. Trigger a run manually using the method described on the Overview page.
  2. Wait 2-3 minutes.
  3. Open the Mule IDP Job Logs list.

Expected result / success criteria: A new row appears for every document library in scope, each with a current timestamp. If an Inbound folder was empty, its row shows FilesProcessed = 0 and Details = "No files found" – that's correct, not a failure.

Result (Pass/Fail)TesterDateNotes
    

TC-02 – Upload & Classify a Timesheet (Required)

Purpose: Confirm a normal file upload and classification works as expected.

Preconditions: A valid sample timesheet PDF.

Steps:

  1. Upload the PDF into a library's 01-Inbound folder.
  2. Set the PDF Type, Site, and Week No. columns on the file to any values.
  3. Trigger a run (or wait for the schedule, if enabled).
  4. Wait 5-10 minutes.

Expected result / success criteria: The file is no longer in 01-Inbound. A new row appears in Job Logs for that library with Status = Success and FilesProcessed = 1.

Result (Pass/Fail)TesterDateNotes
    

TC-03 – Verify the Extraction Output (Required)

Purpose: Confirm the extracted data is correct, not just present.

Preconditions: TC-02 completed successfully.

Steps:

  1. Open 03-Output in the same library.
  2. Open the CSV file corresponding to the file from TC-02.
  3. Compare a few fields (e.g. employee name, daily hours) against the original PDF.

Expected result / success criteria: A CSV file is present and its contents match the source PDF for the fields you checked.

Result (Pass/Fail)TesterDateNotes
    

TC-04 – Verify the Archived File & Retained Classification (Required)

Purpose: Confirm the original file is archived correctly and its classification survives processing.

Preconditions: TC-02 completed successfully.

Steps:

  1. Open 04-Processed in the same library.
  2. Locate the file from TC-02.
  3. Check its PDF Type, Site, and Week No. values.

Expected result / success criteria: The original PDF is present, unchanged, in 04-Processed, and still shows the same classification values you set in TC-02.

Result (Pass/Fail)TesterDateNotes
    

TC-05 – Multiple Files in One Batch (Required)

Purpose: Confirm several files in one run are all handled correctly.

Steps:

  1. Upload 3 valid timesheet PDFs into one library's 01-Inbound at the same time.
  2. Trigger a run and wait 5-10 minutes.

Expected result / success criteria: All 3 files end up in 04-Processed with matching CSVs in 03-Output. Job Logs shows one row for this run with FilesProcessed = 3.

Result (Pass/Fail)TesterDateNotes
    

TC-06 – Multiple Libraries Processed Independently (Required)

Purpose: Confirm one library's files never end up in another library's folders.

Steps:

  1. Upload one valid PDF into Library A's Inbound, and a different one into Library B's Inbound.
  2. Trigger a run and wait 5-10 minutes.

Expected result / success criteria: Library A's file (and only that file) appears in Library A's Output/Processed; Library B's file (and only that file) appears in Library B's Output/Processed. Job Logs shows one row per library.

Result (Pass/Fail)TesterDateNotes
    

TC-07 – Non-PDF File Is Ignored (Required)

Purpose: Confirm non-PDF files are safely ignored rather than causing an error.

Steps:

  1. Upload a non-PDF file (e.g. a .txt or .docx file) into a library's 01-Inbound.
  2. Trigger a run and wait a few minutes.

Expected result / success criteria: The file remains untouched in 01-Inbound. It is not counted in that run's FilesProcessed or ErrorCount, and no error is logged because of it.

Result (Pass/Fail)TesterDateNotes
    

TC-08 – Invalid/Unreadable PDF Routed to Error (Required)

Purpose: Confirm a file the system can't process is safely routed for review instead of getting stuck or silently lost.

Steps:

  1. Upload your deliberately invalid/corrupt PDF into a library's 01-Inbound.
  2. Trigger a run and wait 5-10 minutes.

Expected result / success criteria: The file ends up in 99-Error (not left in Inbound or Processing). The Job Logs row for that run shows Status = Partial Success or Failed, with the Details column mentioning the file name.

Result (Pass/Fail)TesterDateNotes
    

TC-09 – Recovering a File from the Error Folder (Required)

Purpose: Confirm a file can be corrected and resubmitted after failing.

Preconditions: A file currently in 99-Error (from TC-08, or a real one, replaced with a valid PDF if the original was intentionally broken).

Steps:

  1. Move the file from 99-Error back into 01-Inbound.
  2. Trigger a run and wait 5-10 minutes.

Expected result / success criteria: The file is picked up again as a new file on this run (it does not need any special action beyond being placed back in Inbound), and follows the normal success or error path based on whether it's now valid.

Result (Pass/Fail)TesterDateNotes
    

TC-10 – Consecutive Triggers Don't Duplicate Processing (Optional)

Purpose: Confirm triggering twice in quick succession doesn't process the same file twice.

Steps:

  1. Upload one valid PDF into 01-Inbound.
  2. Trigger a run, then trigger it again immediately (within a few seconds), without waiting for the first to finish.
  3. Wait 5-10 minutes.

Expected result / success criteria: Only one CSV and one archived copy of the file appear – not two. The second run's Job Logs row shows the file was already gone from Inbound (FilesProcessed = 0, "No files found") rather than processing it again.

Result (Pass/Fail)TesterDateNotes
    

TC-11 – Scheduled Run Picks Up Files Automatically (Optional)

The automatic schedule runs every hour in this environment.

Purpose: Confirm files get processed without anyone manually triggering a run.

Steps:

  1. Note the current time, then upload a valid PDF into 01-Inbound.
  2. Do not trigger a run manually.
  3. Wait up to an hour, then check the Job Logs list for a new row with ExecutionType = Scheduled and a timestamp after your upload.

Expected result / success criteria: The file is picked up and processed automatically, the same as a manually triggered run would, with no action needed from the tester beyond uploading.

Result (Pass/Fail)TesterDateNotes
