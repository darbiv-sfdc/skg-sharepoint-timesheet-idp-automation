Timesheet Automation – UAT Plan: Overview & Guidance for Testers

This is the first of two pages that make up the User Acceptance Test (UAT) plan for the Timesheet Automation application. This page explains the purpose, scope, and environment for testing, and how to record your results. The second page, Test Scenarios, contains the actual step-by-step test cases.

Purpose

The goal of this UAT is to confirm, from a business user's point of view, that the application correctly picks up timesheet PDFs, processes them, and returns results – and that it behaves sensibly when something goes wrong (a bad file, an empty folder, etc.). No technical knowledge of the application's internals is required to run these tests.

Before you start – what you'll need

  • Read/Contribute access to each document library listed above
  • Read access to the Mule IDP Job Logs SharePoint list
  • Access to trigger a run manually (or a contact who can trigger it for you)
  • At least 2-3 valid sample timesheet PDFs
  • At least one deliberately invalid file for the negative test cases – either a non-PDF file (e.g. a Word document renamed with a .pdf extension won't be needed – a plain .docx/.txt is enough), and one PDF that is either corrupted, blank, or clearly not a timesheet (to see how the application handles a file it can't extract data from)

Important: processing is not instant

After a file is picked up, data extraction happens in the background and can take anywhere from under a minute to several minutes per file. Do not treat "nothing there yet" after 30 seconds as a failure. For each test case below, wait at least 5-10 minutes after triggering before checking results. If results still haven't appeared after that, then treat it as a potential issue and follow the failure process below.

How to record your results

Use the companion results tracker (the UAT test plan spreadsheet/document) to log, for each test case:

  • Pass / Fail
  • The date and time you ran it
  • Anything you observed that differed from the expected result
  • A screenshot, if the result looks wrong (folder contents, Job Logs row, or the CSV file)

If a test fails

  1. Note the exact test case ID, the time you ran it, and what you saw instead of the expected result.
  2. Check the Mule IDP Job Logs list for the corresponding entry and copy the Details column text.
  3. Take a screenshot of the relevant folder (Inbound/Processing/Output/Processed/Error) showing the unexpected state.
  4. Report it to the development/support contact for this project with the above information.

Overall acceptance criteria

This UAT is considered passed when:

  • Every test case marked Required on the Test Scenarios page passes.
  • Test cases marked Optional have been attempted and their results recorded, even if they don't pass – these inform follow-up work but don't block acceptance on their own.
  • No test case leaves a file "stuck" in an unexplained state (i.e. not in Inbound, Processing, Output, Processed, or Error, or in a folder that doesn't match what the test expected) that can't be explained by the test itself.
